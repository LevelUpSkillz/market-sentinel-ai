# Free hosting and acceptance

The new repository is LevelUpSkillz/market-sentinel-ai. No existing Sentinel Intelligence service, database or hostname is reused.

Cloudflare Pages builds a static Next.js export and a same-origin API proxy. The custom domain is market.getlevelupskillz.com. Its new CNAME points to market-sentinel-ai.pages.dev. A separate Cloudflare Access app restricts the custom hostname to the connected account owner. FastAPI independently verifies the signed Access token; the default pages.dev URL cannot bypass backend authorization.

Render configuration is in render.yaml. Both API and database use free plans. The dedicated free database created for this project is market-sentinel-ai-db (PostgreSQL 16, Ohio), expiring 2026-11-22 at 04:35 UTC. Free web services can sleep after 15 minutes of inactivity. No artificial keep-alive traffic is configured. Collection gaps and startup delays must remain visible.

The owner reconfirmed a strict $0 budget. Do not provision a paid service, upgrade the database, or advertise 24/7 monitoring under this configuration. A single Uvicorn process starts the collectors from FastAPI's lifespan independently of browser traffic; the hosting platform can still suspend that process. On resume/restart all books begin unavailable until fresh provider snapshots arrive. PostgreSQL stores paper accounting, watchlists and opportunity history across service restarts.

Collector supervision retries failed background tasks and provider connections with bounded exponential backoff. A socket that receives heartbeats without either subscribed book advancing for 90 seconds is recycled. Stale quotes remain ineligible for fills or recommendations. During Render's overlapping deployment, the new instance stands by until the old PostgreSQL collector lock is released, then subscribes afresh. Readiness checks detect a failed coordinator or stalled persistence, allowing Render to restart an unhealthy process; an exchange outage remains a visible provider outage rather than a restart loop.

Cloudflare Pages runs backend checks, dependency audits, the production Next.js build and Chromium browser checks before publishing the dashboard. GitHub stores source; GitHub Actions is not used for deployment or CI. Render builds the Python service using its own build configuration. Cloudflare build-runner public provider probes are recorded separately from deployed collector acceptance.

Use the Render Blueprint to bind DATABASE_URL through fromDatabase; no connection password is committed. The current service-creation connector cannot securely reference the database connection string. Import the existing database deliberately using its exact database/user names from the Blueprint. SESSION_SECRET is generated by Render. Owner login uses the separate Cloudflare Access issuer and audience already configured for this hostname.

ChangeNOW is read-only and unavailable until a public business API key is stored in backend secrets and the use is approved. Private transaction-management keys are not required. ntfy mobile delivery is optional and must use the owner's private topic. No keys are placed in NEXT_PUBLIC variables.

A Neon free PostgreSQL connection was suggested as a possible replacement for the expiring Render database; it is not connected yet. Free tiers have finite storage/compute quotas and cannot guarantee unlimited permanent retention or continuous collection.

The Blueprint enables documented public Kraken and Hyperliquid reads for the private owner workspace; Coinbase remains disabled. Acceptance requires the production backend to be ready, direct unauthorized data requests to return 401, source timestamps and outages to be visible, paper accounting to survive restart, emergency stop persistence, a real provider connectivity check, and a database export/restore drill. Passing unit tests or an edge persistence measurement does not establish trading profitability.

## Version 0.5 account configuration

Server vault configuration is managed through Render secrets with merge-only updates; the Blueprint omits these keys and must preserve them on sync. Existing `KRAKEN_VAULT_KEY` takes precedence over the dedicated fallback `MARKET_SENTINEL_VAULT_20261024`. Do not rotate either casually or put values into source. `KRAKEN_LIVE_ENABLED=true` permits individually approved own-account USD spot orders only; no connection or trade occurs merely by setting it. Actual deployment flags are verified in DELIVERY.md. Never expose the vault to Pages or `NEXT_PUBLIC_*` variables.

The Cloudflare build uses Python 3.12.14 and build-only pgserver to start a disposable local PostgreSQL. This is acceptance infrastructure, not the production database or a backend migration to Cloudflare. All backend checks must run without skips. No production database URL or credentials are provided to the build runner.
