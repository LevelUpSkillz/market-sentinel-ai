# Security boundaries

Version 0.5 adds private-owner Kraken account reads and individually approved USD spot IOC limit orders. It does not add withdrawals, transfers, custody, leverage, derivatives or autonomous execution. Paper trades remain explicitly simulated records. ChangeNOW implements only a fixed-host GET quote request. Mobile delivery uses a fixed ntfy.sh destination and backend secrets.

Kraken secrets use Fernet encryption with a separate server-only vault key. All unknown/funding/withdrawal permissions are rejected. No credentials enter browser storage, source, responses, logs, audit records or exports. Validation errors do not reflect raw input. Actual balances, fees, lot/tick/minimum rules, fresh CRC-verified books and conservative portfolio limits are checked before an immutable 30-second review. Account/product eligibility requires the owner's explicit confirmation. An exact typed approval is required for every real order. No protective stop is attached; full buy cost counts as at-risk.

Per-key nonces are durable and monotonic. Signed requests use local and PostgreSQL advisory serialization across overlapping instances. Final submission rechecks expiry, profile, connection, emergency stop and current book after lock acquisition, and commits intent before its sole provider POST. Duplicate approvals never resend. Unknown outcomes block subsequent orders until manual reconciliation; absence in a bounded query cannot clear the blocker. Backup restore permanently disables historical order execution and preserves unresolved-order identity without restoring secrets.

Production authentication uses a separate Cloudflare Access application restricted to the owner. The API validates RS256 signature, pinned issuer, audience, issued-at, expiry, token type and exact email against cached public keys. Forged email headers are never trusted. Local password access uses scrypt with a random salt and expiring HttpOnly/SameSite cookies. Production secrets live in hosting environment variables, never source or frontend responses.

Mutations check the configured Origin. API and login rate limits are stored in PostgreSQL. Paper entries have idempotency UUIDs and transactional cash accounting. Single-process collection is enforced with a PostgreSQL advisory lock. The persistent emergency stop blocks paper entries, real Kraken order submissions and push delivery while allowing fresh-book paper exits. It does not cancel orders already accepted by Kraken; inspect the exchange directly. Stale or insufficient books fail closed.

Authentication, watchlist and paper/control operations are audited. The journal is durable but not externally tamper-proof. Readiness checks report database/journal health separately from provider connectivity. Test PostgreSQL must always be disposable and separate from production. Hosted SQLite is rejected.

Known limits: single owner/process, proxy-conservative rate limits, no immutable audit export or formal penetration test, no verified multi-user isolation, and no automatic assurance of database backups. ntfy is at-least-once with bounded retries and can duplicate after a send/commit crash. Commercial/multi-user use requires additional review. The current free Render database expires on November 22, 2026; export or migrate before then.
